# 减重管理医生助手 Product Overview

## 1. 项目目标

`doctor-assistant-agent` 是一个面向医生和健康管理团队的减重管理助手。它的目标不是替代医生做诊断，而是帮助医生围绕减重随访场景更快完成以下工作：

- 判断患者减重进展是否符合预期
- 识别减重停滞期、依从性下降、情绪波动等风险因素
- 整合体重、聊天、随访、知识库等多源信息
- 生成结构化、可追溯、可审计的随访建议

项目当前聚焦的不是泛化医疗问答，而是：

`减重管理随访`

---

## 2. 目标用户与使用场景

### 目标用户

- 医生
- 健康管理师
- 慢病和减重随访团队

### 典型使用场景

- 分析患者近 2 到 4 周减重效果
- 判断是否进入减重停滞期
- 评估患者饮食和运动依从性
- 识别需要加强干预或转人工复核的风险信号
- 生成下一步随访建议或随访任务

---

## 3. 非目标与边界

当前项目明确不承担这些职责：

- 不直接替代诊断决策
- 不直接替代处方开立
- 不面向患者提供自由诊疗结论
- 不作为急症分诊系统

所有高风险建议都必须通过审批链路，所有高危症状都优先触发安全规则和降级逻辑。

---

## 4. Agent 能力地图

当前能力可以拆成 5 层：

### 4.1 数据获取

- 患者档案
- 体重历史
- 聊天记录
- 处方历史
- 随访任务
- 减重管理知识库

### 4.2 减重分析

- BMI 计算
- 体重趋势分析
- 减重停滞期识别
- 饮食/运动依从性分析

### 4.3 随访行动

- 发送提醒
- 创建随访任务
- 发送减重阶段报告

### 4.4 高风险建议

- 起草减重管理方案建议
- 建议转人工医学复核

### 4.5 安全与治理

- 急症关键词拦截
- 高风险建议证据门槛
- 人工审批链路
- 审计日志
- 结构化降级结果

## 5. 工具体系

### 低风险工具

- `get_patient_profile`
- `get_weight_history`
- `get_chat_history`
- `get_prescription_history`
- `calculate_bmi`
- `analyze_weight_trend`
- `detect_weight_plateau`
- `analyze_adherence_signals`
- `get_health_knowledge`

### 中风险工具

- `send_reminder`
- `create_follow_up_task`
- `send_health_report`

### 高风险工具

- `draft_weight_management_plan`
- `recommend_medical_review`

### 关键新工具说明

#### `detect_weight_plateau`

用于识别患者是否进入减重停滞期。默认规则：

- 连续 14 天体重变化绝对值小于 `0.5kg`
- 最近 7 天不存在明显下降趋势

### `analyze_adherence_signals`

用于基于现有数据评估患者依从性。第一版依赖：

- 体重记录
- 聊天记录
- 随访任务
- 处方历史上下文

输出：

- `dietAdherence`
- `exerciseAdherence`
- `overallAdherence`
- `riskLevel`
- `evidence`
- `gaps`
- `recommendations`

## 6. 典型工作流

### 工作流 1：减重停滞分析

输入目标：

> “患者最近两周体重几乎不下降，帮我判断是不是进入平台期并给出建议”

Agent 典型流程：

1. 获取患者档案
2. 获取近 14 到 30 天体重记录
3. 调用 `detect_weight_plateau`
4. 如有需要，再结合聊天记录和依从性分析
5. 输出结构化结果

输出重点：

- 是否停滞
- 证据来源
- 是否需要加强干预

### 工作流 2：依从性下降分析

输入目标：

> “患者最近减重效果不好，帮我看看是不是饮食和运动没跟上”

Agent 典型流程：

1. 获取体重历史
2. 获取聊天记录
3. 获取随访任务
4. 调用 `analyze_adherence_signals`
5. 输出饮食依从性、运动依从性、整体依从性和建议动作

### 工作流 3：高风险建议审批

输入目标：

> “患者近两周减重停滞且依从性下降，帮我起草下一步减重管理方案”

Agent 典型流程：

1. 收集基础资料和证据
2. 形成结构化结论
3. 如需高风险动作，触发高风险工具
4. 创建待审批任务
5. 医生审批后恢复执行

## 7. 结构化输出说明

最终输出不是自由文本，而是结构化结果。

当前核心字段：

- `summary`
- `keyFindings`
- `riskLevel`
- `recommendedActions`
- `needsAttention`
- `uncertainties`
- `supportingEvidence`
- `evidenceSources`
- `inferences`

### 示例

```json
{
  "summary": "患者近两周已进入减重停滞期。",
  "keyFindings": [
    "近14天体重变化小于0.5kg",
    "最近7天没有明显下降趋势"
  ],
  "riskLevel": "MEDIUM",
  "recommendedActions": [
    "复核饮食记录",
    "加强运动执行",
    "安排一次随访沟通"
  ],
  "needsAttention": true,
  "uncertainties": [
    "缺少完整饮食依从性记录"
  ],
  "supportingEvidence": [
    "近14天体重变化 0.3kg",
    "最近7天趋势为 PLATEAU"
  ],
  "evidenceSources": [
    "WEIGHT_HISTORY"
  ],
  "inferences": [
    "当前更符合停滞期而非持续下降阶段"
  ]
}
```

## 8. 证据链设计

证据链是当前项目的重要约束，不允许只给结论不说明依据。

### 证据分类

- `supportingEvidence`
  - 放 Observation 级事实
- `evidenceSources`
  - 放事实来源标签
- `inferences`
  - 放模型归纳判断

### 事实来源标签示例

- `WEIGHT_HISTORY`
- `CHAT_HISTORY`
- `FOLLOW_UP_TASK`
- `PRESCRIPTION_HISTORY`
- `HEALTH_KNOWLEDGE`
- `SYSTEM_RUNTIME`
- `SAFETY_RULE`

### 高风险门槛

当输出构成高风险建议时：

- 至少需要 2 条 `supportingEvidence`
- 必须带 `evidenceSources`

否则系统会阻断该建议并返回安全降级结果。

---

## 9. 安全规则

当前安全规则主要有 3 层：

### 9.1 目标预检

若目标中出现这些高危信号，会直接拦截：

- 胸痛
- 呼吸困难
- 胸闷
- 心悸
- 晕厥
- 自杀 / 轻生

### 9.2 高风险行动前校验

若高风险建议缺少患者档案或体重趋势证据，会被阻断。

### 9.3 最终输出兜底

若最终输出：

- 带有高危症状
- 或高风险建议证据不足

则会降级为安全提示，而不会继续给出激进建议。

---

## 10. 降级策略

当前降级策略覆盖以下场景：

- 模型调用超时或重试耗尽
- 协议解析 / 修复失败
- 达到最大步数
- 恢复执行失败

降级后仍返回结构化结果，而不是只返回技术异常。

### 示例

```json
{
  "summary": "当前模型调用失败，无法完成自动分析。",
  "riskLevel": "MEDIUM",
  "recommendedActions": [
    "请人工接管当前会话",
    "补充近期关键数据后再尝试重新分析"
  ],
  "uncertainties": [
    "当前未获得可用的自动分析结果"
  ],
  "supportingEvidence": [
    "模型调用超时或重试耗尽"
  ],
  "evidenceSources": [
    "SYSTEM_RUNTIME"
  ],
  "inferences": [
    "当前无法安全完成自动分析，需要人工接管或补充数据"
  ]
}
```

## 11. 典型示例

### 示例 1：停滞期识别

输入：

> “患者最近两周体重不怎么下降，帮我判断是不是进入平台期。”

重点输出：

- 是否进入停滞期
- 体重变化事实
- 随访建议

### 示例 2：依从性分析

输入：

> “患者最近减重效果差，想知道是不是饮食和运动执行不到位。”

重点输出：

- 饮食依从性
- 运动依从性
- 证据摘要
- 缺失信息

### 示例 3：高风险建议被拦截

输入：

> “直接帮我给患者调整减重方案。”

若证据不足，系统不会直接进入高风险建议，而是返回：

- 证据不足提示
- 建议补充哪些资料
- 转人工复核建议

## 12. 当前能力范围与限制

当前项目已经具备：

- 减重管理场景收敛
- 结构化输出
- 减重停滞期识别
- 依从性分析
- 证据链约束
- 高风险审批和审计闭环
- 降级策略

但仍有限制：

- 依从性分析第一版仍以规则为主
- 真实模型行为稳定性仍需要评测集验证
- README、API 文档、历史设计文档仍有少量旧表述待持续同步
