# 固定业务回归集 v1

目标是每次修改后重复检查相同的业务约束。固定清单见 [suite-v1.json](suite-v1.json)，通过统一运行器执行现有 Java 测试，输出运行报告。外部模型、存储与服务均使用测试替身，不调用真实患者接口或发送渠道。

## 一条命令运行

从 `governance-suite` 目录执行：

```bash
python3 ai/evaluation-service/run_regression.py
```

默认使用 Maven 离线模式，要求 Java 17、Maven 以及本机已缓存的项目依赖；缺少依赖时会报告失败。需要下载依赖时显式加 `--online`。也可从其他目录使用脚本的绝对路径运行，模块定位不依赖当前目录。

```bash
# 只查看固定组和已知缺口，不执行测试
python3 ai/evaluation-service/run_regression.py --list

# 本地开发检查已有自动化范围，允许报告中的已知缺口影响范围完整性而非退出码
python3 ai/evaluation-service/run_regression.py --allow-known-gaps

# 指定输出目录和每组最长执行时间（秒）
python3 ai/evaluation-service/run_regression.py --output-dir /tmp/ai-regression --timeout 300
```

如果运行环境禁止 Mockito 动态附加 JVM，可使用已安装的 Byte Buddy agent 在测试 JVM 启动时加载，不需要改业务代码：

```bash
python3 ai/evaluation-service/run_regression.py \
  --arg-line='-javaagent:/本机Maven仓库/net/bytebuddy/byte-buddy-agent/版本/byte-buddy-agent-版本.jar'
```

路径与版本应取自本机依赖。该参数只传给 Maven 测试进程，不修改项目配置。

## 固定范围与验收

| 组 | 固定场景 | 通过条件与边界 |
|---|---|---|
| `chat-routing` | 寒暄、画像追问、知识问答、趋势分析、高风险和待审批路由 | 路由、任务类型及原因符合期望；高风险不能被寒暄或画像意图覆盖 |
| `chat-reliability` | 正常连续对话、重复请求、即时完成/失败、缓存回放、会话并发、过载、画像失败 | 对应单元测试断言通过；幂等服务和聊天入口分层验证，不宣称跨实例互斥或完整集成 |
| `agent-safety-degradation` | 紧急目标、缺少证据的高风险动作、模型失败、协议失败、步数耗尽 | 安全短路、阻止工具或返回约定结构的降级结果 |
| `agent-approval` | 批准/拒绝状态同步、批准状态加载、待审批阻止恢复、批准后的流式恢复 | 当前已实现行为符合测试；拒绝后继续执行和并发恢复不在已通过覆盖内 |

路由固定样本升级为 `patient-chat-v2.json`，保留 v1。v2 有 14 条合成样本，新增寒暄夹带风险、画像追问夹带风险、已有意图干扰及正常画像回答。样本里的 `requiredAnswerSignals` 和 `forbiddenAnswerSignals` 只是后续回答审核要求；当前动态测试只验证路由，不据此声称回答质量通过。

## 报告与门禁

每次运行使用独立目录，保存清单快照、固定样本摘要、分组日志以及 `report.json`、`report.md`。仅统计本轮选中测试的新 Surefire 报告；没有新结果、测试缺失、零测试或跳过均不能算通过。某一组失败后继续执行其他组，以便一次看到完整结果。

报告区分：

- `executedGatePassed`：本轮自动执行的测试组是否全部通过。
- `scopeComplete`：清单是否仍存在未完成的场景。
- `gatePassed`：执行通过且范围完整时才为 true。

第一版明确保留五项缺口：拒绝后恢复、并发恢复、流式保护一致性、真实发送回执、真实模型与服务端到端。**所以即使全部离线测试通过，默认总门禁仍不通过，退出码为 2。** `--allow-known-gaps` 仅允许本地已有范围验证使用退出码 0，不会把报告中的缺口或总门禁改成通过。

退出码：`0` 表示所选退出策略通过，`2` 表示测试或范围门禁未通过，`1` 表示配置或执行故障。应同时读取报告，避免只凭退出码判断系统成熟度。

## 维护规则

1. 发现问题时固定触发输入和期望行为，修复时补充失败前可复现、修复后通过的测试。
2. 修改样本输入或期望时创建新版本，保留旧样本；修改组成员或验收范围时创建新的清单版本。
3. 补齐已知缺口后，把对应目标行为测试纳入新版本清单，再移除缺口；不能仅删除缺口来使门禁变绿。
4. 比较结果前确认清单版本与样本摘要一致。报告不自动推断代码、模型或知识库版本。
5. 真实回答评测继续使用现有采集批次和版本对比；此离线回归报告与真实模型评分报告是两类产物。

当前真实采集器只支持独立单轮 `message` 输入，默认请求不带 `customerId`。因此不能直接承接这里带会话状态的路由样本，也不能替代登录患者的 Agent/审批端到端验证。后续扩展测试环境夹具后再将这些场景接入真实调用采集。

仓库上级 `.gitignore` 包含 `*.json`，因此新增清单与样本虽然可以在本地运行，后续提交时仍需显式处理其纳入版本控制的规则；本次未执行 Git 操作。报告目录位于 `target/`，继续作为本地运行产物。
