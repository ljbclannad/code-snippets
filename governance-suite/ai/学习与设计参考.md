# AI 链路学习与设计参考

本文承接原整合时序文档中的设计解释与评估思路。以下内容是分析方法和候选优化方向，不表示功能已实现、性能已测量或已通过上线验收。当前调用顺序以[整合时序](智能对话与医生助手整合时序图.md)为准，建设范围遵循[单实例规范](AGENTS.md#部署范围单实例)。

## 先区分问题发生在哪一层

| 层次 | 要回答的问题 | 证据 |
| --- | --- | --- |
| 身份与会话 | 请求属于谁、是否沿用原会话、是否重复提交 | 身份校验、会话归属、requestId |
| 意图与路由 | 为什么走普通对话、知识问答或 Agent | 原文、意图状态、触发原因、放行结果 |
| 检索 | 候选是否召回，是否被过滤或重排淘汰 | 固定候选集、过滤条件、排序结果 |
| 生成 | 输入是否完整、回答是否有证据支持 | 提示词版本、实际上下文、输出与证据 |
| 执行与审批 | 工具是否真正执行、是否得到审批 | 审计、待办状态、独立执行回执 |
| 后处理 | 回答、历史、搜索与长期记忆是否一致 | MySQL、消息消费、索引和生命周期记录 |

先固定可复现输入和期望，再决定优化哪一层。模型回答错误不一定来自模型，也可能是路由错误、历史缺失或过滤条件不合适。

## 模型调用与参数实验

意图分析、检索改写、回答生成、ReAct、记忆提取、Embedding 和重排承担不同任务。Redis 读写、规则路由和审批状态变化本身不等于模型调用。高风险随访登记和进度查询走固定业务路径。

参数实验应记录模型、提示词、样本、知识与配置版本，并同时比较质量、调用次数、耗时和实际 Token。分类与结构化抽取可实验更低采样温度，回答生成可实验不同输出预算；具体值应由固定样本验证，不能把经验参数写成仓库默认值或质量保证。

Embedding 模型与向量维度须保持一致；更换模型后即使维度相同，也需要评估向量空间兼容性。重排应比较排序收益与额外延迟，保留失败时的可解释回退。

## 上下文为什么需要分层预算

当前问题、患者核心事实、近期摘要、历史问答、长期记忆和工具结果会竞争输入预算。压缩应保护本轮问题和必要证据，避免低价值重复内容挤占空间。

可按以下顺序检查：

1. 源头限制：只检索需要的数据，限制候选数与历史范围。
2. 分区预算：为各类上下文分配预算，计入固定指令和结构开销。
3. 裁剪策略：先去重，再按相关性和时效性压缩，记录被裁剪的信息。
4. 输出验证：比较关键事实保留率、回答证据覆盖率和成本，而不仅是提示词长度。

当前预算规则及历史裁剪行为见[聊天服务说明](ai-chat-service/README.md#模型调用与上下文预算)。本地 Token 估算与提供商计数不同，未知用量应保留未知。

## 为什么检索、记忆和知识库要分开评估

向量相似度、关键词命中和近期记忆启发式分数代表不同含义。把它们归一到相同数值区间，并不代表已经完成概率校准。应固定候选数据，分别评估召回、去重、过滤、重排和最终 top-k；不要同时更换多个环节后把效果全部归因给重排。

记忆还需要验证写入质量：抽取内容是否值得长期保存、重复证据是否强化原记录、冲突是否进入审核、过期和归档是否影响默认召回。知识库则应验证来源、审核、有效期与引用是否匹配。

## 单实例也需要并发与失败设计

单个进程仍有多个请求线程、模型订阅、异步任务和消息消费者。相同请求重试与不同请求同时推进会话是两类问题：前者需要幂等，后者需要顺序保护。取消等待也不等于后台任务已经结束。

讨论断连时，应先确认请求是否有 requestId、是否共享上游、是否收到完成事件、历史是否保存。当前实现的差异见[聊天服务说明](ai-chat-service/README.md#幂等并发与后处理)。

内存账户、缓存和执行计划的重启恢复需要单独说明；单实例定位不会自动带来持久化。数据库历史、搜索索引与长期记忆是不同结果，发送成功或日志出现都不能证明三者一致。

## 性能和上线评估方法

先测每一阶段的 P50/P95/P99、错误率和资源占用，区分模型等待、检索、线程池排队和持久化耗时。可优先评估减少无效调用、缩小上下文、控制候选规模和设置有界队列；性能目标由实际测试环境与业务需求确定。

| 评估类别 | 核心检查 |
| --- | --- |
| 路由 | 风险信号优先级、画像追问误打断、知识问答与 Agent 的边界 |
| 回答 | 证据支持、拒答与安全表达、不确定性、患者与医生输出隔离 |
| 故障 | 模型超时、RPC 失败、队列拒绝、部分结果、重试与重复审批 |
| 数据 | 写入治理、上下文乱序、历史与索引一致性、重启恢复 |
| 成本 | 单轮调用数、Token、工具步数、长尾耗时 |
| 可观测性 | 路由原因、实际版本、降级事件与执行回执是否可追溯 |

离线路由正确、规则评分通过、真实模型质量达标和完整环境验收是不同结论。执行方式及已知缺口以[测试分层](人工智能服务测试分层.md)、[评测说明](evaluation-service/README.md)和[固定回归](evaluation-service/regression/README.md)为准。
