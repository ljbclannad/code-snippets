# 真实调用采集

通过 `ai-chat-service` 的真实同步或流式执行链路收集结果，异步提交到 `evaluation-service` 的固定样本批次。普通对话、缓存/熔断早返回、Agent 升级、错误和流式取消均有采集入口。

采集默认关闭；开启后仍只采集携带 `evaluation` 绑定的测试请求。没有绑定的正常请求不会被导出。采集器不改变评分标准、不调用模型评分器、不审批或恢复医疗任务。

## 运行步骤

以下命令从 `governance-suite` 目录执行。

1. 启动评测服务：

```bash
mvn -f ai/evaluation-service/pom.xml spring-boot:run
```

2. 为独立测试用的 `ai-chat-service` 配置采集：

```bash
export AI_EVALUATION_CAPTURE_ENABLED=true
export AI_EVALUATION_BASE_URL=http://127.0.0.1:8104
export AI_EVALUATION_AGENT_BASE_URL=http://127.0.0.1:8088
export AI_EVALUATION_HASH_KEY='<本地生成且至少16字符的随机密钥>'
mvn -f ai/ai-chat-service/pom.xml spring-boot:run
```

这里的 `ai-chat-service` 仍然需要其原有画像、记忆、消息队列、模型等依赖。请使用独立测试数据与服务配置；本功能没有创建整套基础设施，也不会替换现有连接配置。发送类工具须使用测试接收端。不要将文档中的密钥占位文本作为实际密钥使用。

3. 按实际测试环境填写 `evaluation-service/examples/chat-capture-experiment.json` 的模型、提示词、知识版本，然后执行：

```bash
python3 ai/evaluation-service/collect_chat_evaluation.py \
  --chat-url http://127.0.0.1:8100 \
  --dataset ai/evaluation-service/examples/chat-capture-dataset.json \
  --experiment ai/evaluation-service/examples/chat-capture-experiment.json
```

脚本会注册样本版本、创建批次、逐条调用 `/api/chat`、等待异步上报，收齐后生成正式运行与报告。它不需要手工准备回答 JSON。默认最多 20 次业务请求，每次最长等待 120 秒，采集阶段再等待最多 60 秒；可通过 `--max-calls`、`--chat-timeout`、`--capture-timeout` 调整。不会自动重试业务调用，避免重复触发工具。

`input` 第一版只支持 `{"message":"测试问题"}`。每个样本/轮次使用新的测试会话和请求 ID，缺省使用 visitor 身份，不引用真实患者。带历史或画像的样本会在执行前拒绝，避免静默丢弃测试条件。多轮评测编排尚未实现。

报告位于 `target/evaluation-reports/batch-<batchId>/`。`batch.json` 在调用前写入，用于脚本中断后恢复查询；`invocations.json` 记录每次 HTTP 状态，不包含回答正文。完整采集后保存 `report.json/report.md`，报告可以继续用既有比较 API 做基线/候选对比。

示例只检查成功响应、回复字段及会话关联，并非医学质量验收集。`RECORDED_REAL` 表示来自实际服务调用的记录；缓存、模板降级或 Mock 配置都可能没有调用真实模型，不能据此宣称模型质量验证通过。实验版本由发起方填写；回放中可获得的实际策略版本会另外保存在观测中。

## 手动绑定同步或流式请求

先通过 `POST /api/evaluation/batches` 创建批次，再在原有聊天请求中增加：

```json
{
  "groupId": "evaluation-test",
  "message": "与样本 input.message 一致的测试问题",
  "requestId": "本次测试请求的唯一标识",
  "evaluation": {"batchId": "创建得到的批次ID", "caseId": "样本ID", "trial": 1}
}
```

绑定字段对同步和流式服务均适用；命令行工具目前只调用同步 `/api/chat`。每个 `caseId/trial` 接收一条观测，采集器的 HTTP 重试使用同一个 `captureId` 和相同内容；重新发起聊天应使用新 trial 或新批次，不能用重试业务请求覆盖旧观测。

采集器只记录结果，自动执行测试问题由上述脚本完成。关闭功能时不分配采集状态；异常、队列拒绝或评测服务失败不会改变对话结果。

## 观测内容

| 路径 | 内容 |
|---|---|
| `input.message` | 经过规则脱敏的用户测试问题，必须与注册样本一致 |
| `output.response` | 患者实际回复、成功标志、同步链路可见证据 |
| `output.context` | 实际用到的意图、复杂度、阶段、消息数、版本、最近摘要和待确认问题 |
| `output.routing` | 入口路由决定；缓存等早返回没有此字段，不推断未发生的路由 |
| `output.agentResponse` | Agent 状态、安全回复、结构化分析、证据、降级和复核状态 |
| `output.capture` | 同步/流式模式，request/conversation/run 的 HMAC 摘要，回放采集状态 |
| `output.replay` | 关联运行状态、步骤摘要、工具状态、审批状态、策略版本与结果元数据 |

同步和流式内部都保留完整的 Agent 任务响应供采集。流式 `StreamEvent.evaluationTaskResponse` 使用 `@JsonIgnore`，不会把医生侧结构化内容或新增的运行标识发送给患者。

`replay` 由采集线程调用配置固定的 `GET /api/runs/{runId}/replay` 获取，并核对返回 runId；不会请求审批/执行接口。没有关联 runId 时 `replayStatus=NOT_AVAILABLE`，有 runId 但读取失败时为 `FAILED`，同时将观测记为 `CAPTURE_REPLAY_FAILED`。采集到 `AVAILABLE` 仅说明回放读取成功，工具摘要不是发送成功的独立回执。

流式最终回复由 CONTENT 事件累积。取消、流异常和缺少 DONE 分别标记 `STREAM_CANCELLED/STREAM_FAILED/STREAM_INCOMPLETE`，部分内容不能被计为正常完成。错误原文不导出，以固定错误码保存。同步响应当前没有可靠 Token 计数，保留 null；流式仅使用 DONE 中已有的 Token 用量，不估算。

流式命中降级回答缓存或熔断早返回时，也累积回复事件并在结束时提交采集结果；正常收到 DONE 记为完成，Token 用量保留 null。未携带 `requestId` 的调用在 DONE 前取消时记为 `STREAM_CANCELLED`。带 `requestId` 的调用断连后仍由服务端继续执行，采集以服务端执行的最终状态为准；同一请求的幂等事件回放不会再次采集。采集回调失败不阻断患者回复。

## 脱敏与资源边界

- 使用白名单字段导出，不复制完整用户画像、工作台载荷、步骤原始入参、鉴权信息或完整回放。
- 请求/会话/run 标识使用带本地密钥的 HMAC；已知请求身份标识、常见手机号、证件号和邮箱在文本中替换。短标识采用 ASCII 字母数字边界匹配，避免直接替换所有数字字符。
- 自由文本中的姓名、地址和其他个人信息无法由这些规则全面识别；只使用合成或预先脱敏的测试材料。摘要和医疗文本本身仍可能敏感，JSON 记录不应公开共享。
- 默认文本上限 16000 字符、嵌套深度 12、数组 100 项。截断会标记 `CAPTURE_TRUNCATED`，不会把不完整记录当作正常结果。
- 单独 1 个采集线程，队列默认 128；网络连接和读取超时各 1500 ms，上报最多 2 次，4xx 不重试。目标地址仅来自服务配置，不能由请求指定。
- 队列满、进程退出或网络故障可能丢失尚未确认的观测；当前不是可靠消息队列。评测端已经确认的记录会持久化。缺失结果会保持批次未收齐，不会自动算通过。

配置项统一位于 `ai-chat.evaluation-capture`，包括 `queue-capacity/timeout-ms/max-attempts/max-payload-bytes/max-text-length`。评测服务默认仅监听本机，没有认证；跨机器部署需另外配置网络访问控制。

## 查看与排查

`GET /api/evaluation/batches/{id}` 查看数量及状态；`GET .../{id}/report` 随时预览，其中未采集样本计为 ERROR。
全部收齐后 `POST .../{id}/finalize` 生成正式报告（重复调用幂等）；收齐不代表规则全部通过。
脚本超时会导出缺失结果的预览并以退出码 2 结束，不会伪造成功观测或强制完成批次。

`ai_chat_evaluation_capture_total` 指标通过 `result` 标签区分 `started/queued/delivered/retry/replay_failed/delivery_failed/queue_rejected/snapshot_failed/invalid_binding`。
日志不输出采集载荷或远端错误正文。如果收不到结果，依次检查是否启用采集、是否有绑定、样本消息是否匹配、回放端口是否正确，以及这些指标。

## 验证

```bash
mvn -f ai/ai-chat-service/pom.xml test
mvn -f ai/evaluation-service/pom.xml test
python3 -m unittest discover -s ai/evaluation-service -p 'test_*.py'
```

测试覆盖 disabled/unbound、异步快照、重复完成、HTTP 重试、队列拒绝、脱敏、回放关联、同步早返回、流式完成/取消/错误、不完整输出、批次幂等冲突及重启恢复。`AiChatStreamServiceTest` 另行覆盖流式缓存与熔断早返回的正常上报、DONE 前取消和采集回调失败不影响回复。真实模型质量和完整基础设施联调需在准备好的测试环境中另行执行。
