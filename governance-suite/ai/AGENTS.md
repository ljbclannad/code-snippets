# AI 服务体系开发规范

本文件约束 `ai/` 下的开发、审查和验证。仓库通用规则继续生效；项目导航见 [README](README.md)。

## 部署范围：单实例

- AI 项目按单实例设计、开发和验收：同一环境中，每个可部署的 AI 服务仅运行一个应用进程；各服务仍独立运行并通过 HTTP、RabbitMQ 等协作，公共 JAR 不单独部署。
- 代码审查、优化与测试以单实例为边界。多副本部署、跨实例互斥与幂等、共享 HTTP 会话、分布式配额和多活一致性不属于需求、待办或验收缺口；仅在用户明确改变部署目标后再评估。
- 单实例仍需保障并发请求、同步与流式入口协调、重试幂等、异步任务、审批事务、依赖故障和进程重启后的数据恢复。内存状态的重启丢失风险应如实记录。
- 本地与服务器运行同一服务时使用隔离的业务数据、消息队列和服务发现环境；同一环境更新服务采用先停旧进程、再启新进程的方式。
- 现有实例隔离实现和相关回归测试可以保留；不为单实例定位主动删除已有保护，也不扩展多实例能力。

## 模块职责与阅读入口

修改前先定位目标模块，只阅读和修改任务需要的范围。

| 模块 | 职责 | 修改时阅读 |
| --- | --- | --- |
| `ai-chat-service` | 患者入口、会话、画像与记忆编排、对话和升级路由；不管理画像或向量存储 | [聊天说明](ai-chat-service/README.md) |
| `user-profile-service` | 画像、偏好、候选字段与冲突治理；不存储对话历史或检索向量 | 该模块 `service/`、`mapper/`、`entity/` 与 [数据库指南](数据库初始化说明.md) |
| `vector-memory-service` | 长期记忆抽取、向量检索、重排和生命周期；短期会话属于聊天服务 | [模块说明](vector-memory-service/README.md) |
| `doctor-assistant-agent` | 已升级任务分析、医生结构化结果与人工复核；不承担患者聊天主入口 | [模块说明](doctor-assistant-agent/README.md)、[工程指南](doctor-assistant-agent/docs/减重管理医生助手工程指南.md) |

## 修改约束

- 默认由主代理完成；仅在用户明确要求时使用子代理。
- 开始修改前阅读相关代码、约定与测试；缺陷先建立可复现证据，修复时补回归测试。
- 优先最小可验证改动。未经用户明确要求，不进行跨模块重构，不因目录相邻修改无关文件。
- 修改 `common` 或 `agent-platform-common` 前列出实际消费者，分别安排受影响模块的编译或测试。
- AI 模块不引入 Seata、ShardingSphere 等分布式治理依赖；未经用户明确要求不修改 Spring AI 版本。
- Java 标准库工具类显式导入，不在业务代码中使用全限定名调用。
- 仅在用户明确提出 Git 相关请求后执行 Git 操作；提交、推送、创建 issue、发布或删除文件前取得明确授权。

## 模型、上下文与医疗边界

- 模型访问沿用 Spring AI 的 `ChatClient`、`ChatModel` 或现有流式抽象，配置超时、重试与可观察的降级；API Key 仅通过环境变量提供。
- 修改上下文构建时计入 Token 预算；增加检索路径时覆盖超时和降级；修改记忆检索算法时提供同一数据集的 A/B 结果，验证召回与准确率。
- 修改 Milvus 连接需验证连接，修改向量维度需准备索引重建方案；这些验证需要真实环境时如实报告前置条件。
- 画像字段或持久化结构变更提供可审阅的迁移脚本；API 保持兼容或明确版本边界；评分、画像补全和生命周期规则变化同步文档。
- 医生场景沿用当前 `TaskType`、`PatientTaskAgentService` 与场景工具注册结构。先定义输入、输出和安全约束，再实现并补单元及集成测试、更新接口说明。
- 当前医生 ReAct 通过严格 JSON、解析校验和协议纠偏驱动工具调用；修改时保持结构化输出兼容，未完成的 JSON 增量不能直接执行。
- 保持 `patientSafeReply`、患者证据与医生侧 `structuredResult`、`doctorWorkbenchPayload` 的边界，并增加输出兼容性测试。最终医疗决策及受控动作遵守医生复核流程。
- 知识导入验证质量与完整性；增加知识类型时先定义数据模型。记录与评测使用合成或已脱敏材料。

## 异常与可观测性

修改失败处理时，明确该路径的超时、重试条件、患者响应、数据是否已写入和后续恢复方式。画像不可用与空画像、模型失败与无有效结果应区分；不能把统一重试次数或死锁自动恢复写成尚未验证的能力。

修改降级策略时同步文档和实际指标。关键事件记录 INFO，重试和降级记录 WARN，依赖/API 失败记录 ERROR，调试细节使用 DEBUG；日志避免真实患者文本、凭据和完整敏感载荷。跨服务排障保留会话与请求关联，使用现有 Micrometer 指标和追踪机制。

运行环境、Nacos、密钥注入与排障见[运行指南](本地运行与排障.md)。敏感配置使用环境隔离和安全存储，不能把开发配置当成已验证的生产配置。

## 构建与验证

命令从 `governance-suite` 根目录执行。先运行与改动匹配的定向测试，再按风险扩大到模块：

```bash
mvn -f ai/ai-chat-service/pom.xml compile
mvn -f ai/ai-chat-service/pom.xml test
```

替换为实际目标模块。共享改动仅扩大到受影响消费者。具体测试选择、外部依赖参数、固定回归与真实模型评测见[测试分层](人工智能服务测试分层.md)。

- 核心逻辑维护单元测试，Mock 外部依赖；覆盖率目标为大于 60%，声称达标需提供实际报告。
- 涉及模型降级、记忆检索、路由或审批时覆盖正常、失败和重试路径；性能改动比较对应延迟、吞吐与降级表现。
- 启动、Nacos 注册、API、监控和日志检查仅在对应改动及环境适用时执行；公共 JAR 和独立评测服务不套用业务服务启动清单。
- 报告实际运行命令与结果。外部环境未就绪时标明未执行项，不能以离线测试通过替代端到端通过。
- 纯文档修改检查链接、锚点、示例路径和事实依据，不为此执行全量构建。

## 文档维护与完成标准

- 代码变更影响接口、配置、数据库、启动、监控或重要行为时，同步更新对应说明。
- 总 README 维护导航；跨服务时序、模块契约、运行操作、测试和设计讨论各自维护，其他位置用链接引用。
- 当前实现、已知限制和候选设计明确分开。已实现能力不能继续列为待建设，多实例能力不列为项目缺口。
- 文档命令写明工作目录。数据库步骤区分初始化与增量迁移，不能把基础脚本当成完整迁移器。
- 根 `.gitignore` 包含 `docs/`；新增说明优先放到已有模块 README 或 AI 顶层专题。修改既有 `docs/` 文件时报告这一交付限制；未获 Git 请求时不通过 Git 查询或改动跟踪状态。
- 完成时说明改动范围、验证证据和未验证项，引用准确文件路径。
