# 幂等、防重与秒杀

这部分覆盖两个常见但容易混淆的点：

- 普通接口幂等
- 高并发秒杀下的削峰和防重

## 普通下单幂等

`order-service` 通过 `Idempotency-Key` 和 Redis 锁避免重复提交。

学习重点：

- 为什么客户端重试时需要幂等键
- 幂等不等于“什么都不做”，而是“重复请求不会产生额外副作用”
- Redis 幂等键只是第一层，复杂场景通常还要配合数据库唯一约束

## 秒杀链路

秒杀接口 `POST /order/v2` 的核心动作在 Redis Lua 中原子完成：

1. 校验库存
2. 判断是否重复购买
3. `DECR` 预扣库存
4. `XADD` 写入 Stream

随后由异步消费者落库、扣减正式库存、写 Outbox。

## 为什么这么设计

- 先在 Redis 做原子判断，降低数据库竞争
- 用 Stream 承接突发流量，避免所有请求都同步压到 DB
- 用数据库唯一索引兜底，防止异步阶段重复落单

## 建议实验

- 同一 `Idempotency-Key` 连续请求两次普通下单
- 对同一用户连续请求两次秒杀接口
- 准备极小库存，连续请求多次，观察 `SOLD_OUT` 与 `DUP_BUY`
